## 工具缺陷与修复证据

### 已修复：`duration` 缺少格式验证

原实现仅把 `duration` 当成非空字符串，因此 `"未知"`、`"01:02"` 或分钟/秒溢出值均会通过。新增 `INVALID_DURATION`：接受 `H:MM:SS`、`HH:MM:SS` 及更长小时数（多位小时不以 `0` 开头），要求分钟和秒为 00—59。

这兼容 3 篇真实数据的 `1:15:49`、`4:15:31`、`5:18:56`，也与飞书长时录音的展示方式一致。

### 已修复：锚点未与会议时长交叉校验

原实现会接受形状合法但晚于录音结束时间的锚点。新增 `ANCHOR_AFTER_DURATION`，覆盖：

- `coreTopics[].anchor`
- `discussion[].anchors[]`
- `sourceAnchors[].time`

锚点恰好等于 `duration` 允许通过；`duration` 非法时不产生连带越界错误，避免重复噪声。

## 仍需保留的人工判断

- `contentStatus` 的定义目前只有枚举和 `insufficient` 的最低要求，没有可机械证明 `complete` 或 `partial` 的充分条件。首批 3 篇的状态需要继续依赖 `limitations`、来源覆盖和审稿人判断。
- 工具只能确认锚点格式、范围与结构，不能在不读取私有逐字稿的情况下确认锚点主题与原始发言是否语义一致。
- 工具能检测完全或规范化后相同的页面，不能可靠判断“换写后的语义重复”。跨页主题重叠仍需人工审阅。
- 敏感扫描是发布阻断的防护网，不是法律、隐私或事实核验的替代品；复杂身份线索和间接可识别组合仍需人工检查。

## 建议

1. 后续新增会议时继续保留 `partial / medium` 的清晰理由，不要因正文较长自动升级为 `complete`。
2. 若要机械强化状态语义，应先在 schema 中定义各状态的可验证判定标准，再增加测试；不要从当前 3 篇反推武断阈值。
3. 每批内容合入前固定执行 `npm run test:coverage` 与 `npm run content:check`，并抽查最长时长页面的最晚锚点。
