## 抽样设计

采用可复现的分层系统抽样，而不是按内容好坏挑样：

1. 以 `grounding-2026-08-24` 为固定种子，对公开 slug 排序；从每个日期的锚点数不少于 3 的页面中先取 1 页。
2. 强制纳入按同一种子排序后的首个 `sourceAnchors=[]` 的 `insufficient` 页面，使现存 `partial` 与 `insufficient` 两种状态都被覆盖。
3. 从其余锚点数不少于 3 的页面中按种子顺序补至 12 页。对每个锚点非空页，系统选取 `sourceAnchors` 的首条、中位条和末条；零锚点页改查来源是否确实没有任何发言记录。
4. 每个时码均回看原始转写中的该发言块和邻近上下文，依次判断：时码是否精确存在、公开 `note` 是否脱敏且不过度概括、同一时码关联的 `coreTopics` / `discussion` 是否有语义支撑。关联字段使用同一段多个时码时，本次只判断抽中时码是否支持其对应子命题，不把单一时码当成整段全部论断的唯一证据。
5. 本报告不记录来源标识、私有路径、说话人或原句；“通过”仅表示这三项人工检查在本次样本内通过。

## 结果

### 时码存在性

33 个抽样时码均能精确匹配原始转写中的相对时间戳。没有发现估算时码、错误分段或只落在录音结构位置而没有对应发言的情况。

### 去敏 note

33 条公开 `sourceAnchors[].note` 均为主题级转述，没有复刻原句，也没有写入说话人、私有资源标识或可直接识别个人的细节。涉及背景媒体、第三方传闻、私人片段和商业敏感讨论的样本，note 均以“排除、边界、待核验或泛化”表达；没有把这些内容升级为已证实事实。

### core / discussion 语义支撑

抽中时码关联的 `coreTopics` 与 `discussion` 均能在该发言块或其紧邻连续上下文中找到对应语义。公开文本普遍把经验判断、技术猜测、商业数字和平台说法降格为会议观点或待验证项，并把额外的治理建议清楚写成可迁移做法，没有伪装成会议已经形成的事实或决定。

其中几类高风险样本也通过：

- 背景教程、媒体内容、传闻与生活片段只用于说明来源边界，没有被归给参会者或写进业务结论；
- 残句和长空档页面明确保留低置信度及覆盖不足，不从标题补全议程；
- 零锚点 `insufficient` 页的来源确实只有基础元数据与空关键词区，没有任何发言块；页面的“无可用转写”表述成立，且没有生成会议主题；
- 涉及融资、定价、增长、产品效果和工程根因的公开段落保留了待核验、假设或无日志限制，没有把口头说法写成可审计事实。

## 局限

- 这是 12/30 页、33/783 条锚点的人工抽样，不等价于逐页逐锚点全量事实审计；未抽中的页面或锚点仍可能存在问题。
- 系统首—中—末抽样提升了时间跨度覆盖，但不会自动覆盖每页风险最高、争议最大或文字最长的断言。
- 一条 `discussion` 常由多个锚点共同支撑；本次核查抽中锚点对相应子命题的支撑，未逐一复核该段所有其他锚点。
- 原始材料只有转写文本，本次没有核听音频、核对画面、日志、合同、后台或外部权威资料，因此只能确认“公开提炼忠于转写且标注边界”，不能确认会中陈述本身为真，也不能评估转写识别错误。
- 去敏判断限于公开文本与当前上下文；无法证明不同页面、外部资料或未来发布内容交叉组合后绝对不可再识别。
